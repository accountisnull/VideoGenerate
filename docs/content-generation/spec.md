# 内容生成与改稿规格

依据：2026-09-23 人员 5 任务单，以及用户“先按照我的任务进行开发，最后再进行处理”的指令。此次聚焦人员 5，整体架构、旧目录和其他成员的文档最后统一处理。

## 目标与行为

- F1：根据必填主题、可选来源稿件和可选素材生成一份口播正文、发布标题、标签和素材引用；无素材仍保留主题，不声称完成实时检索。
- F2：根据完整上一版本，以及审核问题或明确修改意见，生成新版本；保留前后版本关联，原稿不变。只有意见没有原稿时拒绝调用模型。
- F3：正文按去除全部空白后的字符数计数，包含标点，暂定 100—200 字；标题、标签单独输出，标签去除井号并按顺序去重。输出缺字段、空白、类型错误、长度错误和未知素材引用均明确失败，不补造内容。
- F4：写稿和改稿使用现有配置指定的不同模型；每次操作最多发起一次模型生成请求，记录调用次数、耗时及使用模型。请求超时、调用失败、输出无效与业务审核不通过分别表达。
- F5：来源素材和旧稿作为参考数据，不赋予其修改系统规则的权限。生成器交付待审核稿件，不宣告审核通过。

## 范围

提供可由编排层调用的接口、Skill 指令、示例、自动化测试和真实模型验证入口。编排层负责作业持久化、来源所属生产任务校验、修订轮数、全套审核与后续配音。自动选题、客户历史学习、MCP 服务、数据库替换、前端和发布不在此次实现中。

## 验收

- AC1（F1/F3）：有素材和无素材输入均能走完整生成与校验流程；伪造引用、错误 JSON、空输出、缺字段和超长正文有可观察错误。
- AC2（F2/F3）：改稿保留完整原稿和反馈，返回独立版本并关联原稿；原输入不变，标签格式和字符数符合要求。
- AC3（F4）：分别选择写稿/改稿配置，禁用隐式重试；超时和失败可区分，记录不会暴露密钥或上游异常正文。
- AC4（F5）：提示模板区分规则和参考材料，返回结果无审核通过声明。
- AC5：现有测试及新增测试、静态检查通过；真实调用另行记录，有凭据和可用模型才执行。
- AC6：真实规则/模型审核和配音可朗读性由对应成员联调验证，未执行时明确标记未完成。
