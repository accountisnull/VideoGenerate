# 内容审核与存储设计

在现有内容主管接口上补齐严格审核与可恢复存储，不另建状态机或通用写表服务。

## 审核

`AuditReviewer.review(ReviewInput) -> ReviewDecision` 复用 `TextCompletion` 和
`TEXT_REVIEW_*`。一次请求同时审核原主题、正文、标题及标签。模型仅产生
passed 和 issues；每个问题必须含 field、code、message、suggestion。
规则版本、规则内容摘要、模型配置 ID、提示词版本和耗时由程序补充，不能由模型自报。
既有关键词审核继续使用原 Issue，新增 suggestion 为兼容字段；HTTP 公共契约不变。
模型 JSON、类型、结构、决定与问题不一致时失败关闭，供应商异常不转为业务拒绝或通过。
规则文件与关键词审核使用同一份 ContentRules 快照，不在两轮之间重读。

## 存储

沿用 ContentStore 的作业受理、claim、finish 与调用日志接口。新增按 caller_id
隔离的完整记录查询，返回原始规范化请求、调用意图与结果、最终 outcome。
阶段和轮次沿用调用日志中的 stage 和 input_json；不维护第二份业务状态。
v1 到 v2 在 BEGIN IMMEDIATE 事务中升级，增加作业调用索引与数据库终态保护。
未知版本、其他应用数据库拒绝启动；迁移失败回滚结构与版本，旧记录不删除。
备份使用 SQLite backup API，并拒绝覆盖已有文件。

恢复继续由持有 ServiceOwnership 的主管执行：queued 可启动；running 明确失败为
EXECUTION_INTERRUPTED，保留未完成调用，禁止自动重复模型请求。
向量调用允许只读核对后补记结果，但不能改写已失败作业的终态。

## 实施与验证

1. 先添加审核坏 JSON、错类型、缺建议、一次调用、版本追踪测试，再实现适配和组装。
2. 添加旧库升级、失败回滚、并发幂等、终态保护、重启查询、备份测试，再补齐存储。
3. 提供正常、问题、主题偏离、标题及标签问题的标注候选样例和独立实测命令；
   样例需人工复核，示例规则不冒充正式规则。实际响应与本机报告不提交 Git。
4. 运行全量 pytest、Ruff 与差异检查，提交任务分支并推送；PR 交由其他成员评审。

人员 2 需核对正式词表与规则版本，人员 5 需核对 suggestion 字段，人员 6 需评审
迁移、存储和兼容组装。真实模型配置缺失时如实记录未验收，不以替身测试替代。
