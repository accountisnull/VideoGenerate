# 成员开发任务入口

本文供成员与其 Codex 开始任务时共同阅读。接口候选基线和目录、启动安排已由陈思锴确认，其他成员的接口兼容性反馈仍待收集；共享批次方案见 [协作开工对齐](协作开工对齐.md)。

## 全员先读

1. [AGENTS.md](../AGENTS.md) 与 [开发规范](开发规范.md)：中文说明、开闭原则、保留他人修改、单工作目录、逐次推送授权和成员 PR 审批。
2. [领域词汇](../CONTEXT.md) 与 [技术框架](技术框架.md)：首版只打通单条真实生产与发布链路。
3. [HTTP 接口协议](HTTP接口协议.md) 与 [公共数据契约](contracts/README.md)：以远程 `2d8cf2c` 已有公共模型为首轮候选基线，具体状态见对齐记录。
4. [安装说明](installation.md)：每位成员在自己的电脑准备环境，不复制其他人的虚拟环境、密钥或运行数据库。

开工先报告分支、工作区状态、负责模块及未满足的前置条件。按任务需要阅读相关代码；环境和资料准备可以先推进，接口分歧明确反馈后共同处理。不得因为缺少真实模型而用假成功代替真实交付。

## 程贺龙：内容生成

- 任务分支示例：`feat/content-generation`；代码放 `backend/app/content/`，规则放 `backend/skills/`，测试放 `backend/tests/content/`。
- 复用 Python 3.11、content 依赖组和公共模型，接入百炼并实现写稿、检查、改稿。具体模型、检查规则和返工上限需登记，密钥只放本机服务端。
- 提供 `/v1/content` 下的 health、capabilities、作业提交和查询；结果是通过检查的口播稿、标题和标签，不将未通过稿件交给下游。
- 交付 `scripts/start-content.ps1`（默认 8761）及 `docs/content-service.md`，包含环境安装、配置、启动停止、测试和真实样例说明。
- 首份交付：一份真实结构化内容、正常与失败场景、幂等及重启查询证据。杨子祥核对可朗读性，陈思锴核对契约。

## 杨子祥：配音

- 任务分支示例：`feat/speech-service`；代码、模型依赖与测试在 `backend/tts/` 内独立维护，测试目录为 `backend/tts/tests/`。
- 选择 TTS 与音色，登记运行环境、文本限制和实测音频规格。接收最终口播稿，不自行改写内容；输出完整最终配音与摘要、时长、编码、采样率和声道信息。
- 提供 `/v1/speech` 下的四类入口；维护自己的作业与幂等记录，不读取集成数据库。
- 交付 `scripts/start-speech.ps1`（默认 8762）及 `docs/speech-service.md`，说明独立环境安装和自检方式。
- 首份交付：约 10 秒真实配音及测试证据。李宇昊验证模型兼容，陈思锴核对文件交接；后续扩展至约 30 秒样例。

## 李宇昊：数字人

- 任务分支示例：`feat/avatar-service`；代码、模型依赖与测试在 `backend/avatar/` 内独立维护，测试目录为 `backend/avatar/tests/`。
- 选择数字人方案，准备一个可用人物资源，登记音频输入限制、视频输出规格、运行环境和算力要求。人物管理页面与日常素材维护人的归属另行确认。
- 提供 `/v1/video` 下的四类入口；消费杨子祥交付的同一份最终配音，产出视频、源音频摘要、实测规格和时间偏移。
- 交付 `scripts/start-avatar.ps1`（默认 8763）及 `docs/avatar-service.md`。
- 首份交付：使用真实样例配音生成的口型视频，附格式探测、完整时长覆盖及人工嘴型检查结果；不兼容基线时说明限制，不静默变更规格。

## 陈思锴：集成与发布

- 后续任务分支示例：`feat/generation-pipeline`；当前存储、HTTP 任务仍按现有本地任务安排处理，不为新任务擅自清理未提交文件。
- 负责集成 API、生产任务存储、Worker、调用适配、音画合成与发布核实；目录与依赖沿用 [项目目录](项目目录.md) 的集成约定。
- 整理本地存储与 HTTP 实现的交付范围，记录验证所对应的版本。生产 Worker 尚未接通，现有 `scripts/start.ps1`（默认 8765）仍以自检 Worker 为主。
- 接入三个服务时持久化请求、幂等键、作业编号和阶段结果，核验资产，再合成最终 MP4；发布结果不明先核实，不重复提交。
- 同时推进发布应用、账号权限和规则内容准备。前端、人物维护和规则维护人员由小组明确，不默认为陈思锴独自承担。

## 统一交付清单

- 三个生成服务的启动脚本支持 `-Port`、`-AssetRoot`，不依赖调用者当前目录；缺依赖或配置时明确报错。脚本、服务代码和说明由成员实现，不将约定路径当成现成入口。
- 配置、依赖、启动停止、就绪检查、四类 HTTP 入口和测试命令均有说明。后台运行时有本服务的进程识别与停止方式，不误停其他程序。
- 临时目录或替身测试覆盖正常、失败、重复请求及重启行为；真实推理与媒体质量另附证据。独立服务测试要实际收集自己的测试目录。
- 交接的文件摘要、大小和媒体参数来自实测；真实密钥、模型权重和业务素材不入库。样例可另行交接并核验摘要。
- 提交与推送是分开的授权，任务完成不自动推送。公共契约改动协调相关成员，PR 至少另一名成员审批。
