前三个服务分别实现四类入口：

| 方法及路径（`<模块>` 为 content、speech 或 video） | 交付要求 |
| --- | --- |
| `GET /v1/<模块>/health` | 返回服务就绪情况，不触发收费推理 |
| `GET /v1/<模块>/capabilities` | 返回实际支持的配置档与资源 |
| `POST /v1/<模块>/jobs` | 校验并持久化受理后返回作业，首次 202、准确重放 200 |
| `GET /v1/<模块>/jobs/{job_id}` | 查询已有作业的状态、结果或错误 |

集成端负责编排这些服务，三个模块不互相调用，不直接发布抖音。陈思锴的本地生产存储和 HTTP 实现尚未共享，不要求前三个服务依赖这些实现，也不允许直接读取集成数据库；各服务负责自己的作业与幂等记录。

### 共同遵循的行为

1. 请求编号用于追踪，UUID 幂等键用于防止重复创建；POST 超时后按原请求、原键核实或重试，不能随意换键。
2. 模块作业使用 `queued / running / succeeded / failed`，终态不可变。HTTP 查询成功与业务执行成功分别表达；生产任务的完整状态另按协议执行。
3. 请求拒绝未知字段，响应允许增加可忽略字段；必填的 `null` 必须保留，明确区分可空与可省略。各模块复用公共模型，独立环境不兼容时可使用生成的 Schema 并补齐业务校验。
4. 文件位于统一资产根目录，HTTP 只传相对路径、真实大小与摘要。完整写入后才能返回成功，消费前检查真实文件和目录边界。
5. 配音、口型视频、成片关联同一份最终配音，不能自行裁剪、变速或替换后仍声称是原配音。失败与重做保留来源记录。
6. 每个模块实现重启后的记录查询，无法恢复执行时明确失败，不静默重复收费调用。集成 Worker 的流程恢复由陈思锴另外负责。
7. 媒体按已确认规格先实测约 10 秒、再约 30 秒样例；两者是验证样例，不是默认服务容量上限。样例素材不提交 Git。

### 服务地址与启动交付

| 服务 | 已确认默认地址 | 启动入口与责任 |
| --- | --- | --- |
| 内容 | `http://127.0.0.1:8761` | 程贺龙交付 `scripts/start-content.ps1` |
| 配音 | `http://127.0.0.1:8762` | 杨子祥交付 `scripts/start-speech.ps1` |
| 数字人 | `http://127.0.0.1:8763` | 李宇昊交付 `scripts/start-avatar.ps1` |

8761—8763 是可配置默认值，不保证成员电脑上端口空闲。服务和调用方通过配置保持一致，不在业务代码中写死。三个新增脚本是待实现交付项，当前不能直接运行；它们只负责各自服务，现有 `start.ps1` 暂不扩展为一键启动所有模型。

三个新增脚本按本次约定支持 `-Port` 和 `-AssetRoot`：前者覆盖本服务默认端口，后者指定共享资产根目录，默认解析为仓库 `data/assets/` 的绝对路径。脚本不依赖调用者当前目录，使用对应服务的解释器或模型环境，缺配置时明确失败；具体配置字段在实现时同步 `.env.example` 和服务说明，不预先宣称已支持。

独立开发时可在前台运行服务并记录 Ctrl+C 停止方式；需要后台运行时，交付能识别本服务进程的状态和停止入口，不误停其他进程。完整安装、自检、启动和停止命令由各模块 README 给出，并由负责人在自己的环境实测。

当前集成 `start.ps1` 启动的是 API 与环境自检 Worker，不会因此自动具备生产执行能力。现有脚本的 `-Port` 和配置边界维持当前行为。

### 数据交接与第一轮验收

- 同机联调的所有模块指向同一物理资产根目录，协议只传根目录内的相对路径；各人机器上的本地路径不能直接互相读取。开发样例通过约定方式复制到接收方资产目录后核对摘要，不能把另一台电脑的绝对路径放入接口。
- 各模块的作业数据库和运行状态独立保存并忽略提交，不读写集成 `app.db` 的内部业务表。模型权重、凭据、日志和媒体素材不入库，新增目录时补齐忽略规则。
- 程贺龙交付内容契约测试及一份真实结构化内容；杨子祥交付配音契约测试及约 10 秒样例；李宇昊用这份配音验证口型视频并提交实测规格。服务均须验证 health、capabilities、提交和查询四类入口，以及重复请求与重启行为。
- 陈思锴核对每个服务的启动说明、配置、契约和真实样例，再组织联调。后端既有测试与 Ruff 按项目约束执行；独立模型服务另交付自己的测试命令，不能用集成测试通过代替模型验证。
