## 模型及固定口径

- 模型：`BAAI/bge-m3`，使用用户提供的本地 `pytorch_model.bin`，dense 稠密向量 1024 维。
- 模型版本：`local-sha256:2b0617a475299ad48c2346dcab71d07f7adb4887694de1edb4c0fba6b858bd41`。
- 索引版本：`bge-m3-dense-cls-l2-cosine-v1`。模型 ID、指纹、维度、pooling、归一化、距离、预处理和索引版本均保存在集合 metadata 及记录 payload 中。
- CLS pooling、L2 归一化、Cosine 分数，双方原文、不加单侧检索指令。只用 dense，不启用 sparse/ColBERT。
- 检索 top 10，先过滤当前 content_version_id，最高分 **>= 0.85 拦截**。0.85 不是文字重复率。
- 输入不静默裁剪；模型上限 8192 token（不是汉字数），超长失败。缺失权重、变更指纹、维度不符、零/非有限向量都失败。
- 本期固定单文件 .bin 部署；新增 safetensors/分片索引会拒绝，防止第三方库优先加载未经登记的其他权重。切换格式需显式新部署和索引版本。
- CPU 推理，2 个线程，无需 API Key；每次请求使用独立子进程加载/推理，120 秒硬超时包含模型加载和摘要核验。此实现优先可复现和故障隔离，未做常驻模型性能优化。
- 权重约 2.27 GB；应预留权重及运行内存空间。本机已实测可运行，未测内存峰值，不承诺团队 P50/P95 或十并发性能指标。

### Qdrant 本地磁盘模式

不需要 Docker、网络端口或额外数据库进程。首次明确创建集合：

```powershell
.venv/Scripts/python.exe -X utf8 -m app.content.cli init
```

以后启动只校验，不自动创建缺失集合。配置不兼容时拒绝操作且保留旧库。本地磁盘目录仅由一个进程拥有：CLI 退出即关闭，MCP 进程退出即释放；不要同时启动多个访问同目录的 CLI/MCP 实例。多个调用方应连接同一个主管/适配服务，或使用下面的 Qdrant 服务端。

### Qdrant 服务端模式

```powershell
docker run --detach --name content-qdrant -p 127.0.0.1:6333:6333 -v content-qdrant-data:/qdrant/storage qdrant/qdrant:v1.19.1
docker stop content-qdrant
docker start content-qdrant
```

使用持久 Docker volume；停止不删除数据。配置 PATH 留空，URL 改为 `http://127.0.0.1:6333`，执行同一 init。HTTP 请求超时默认 10 秒。此交付为可信单机内部服务，不暴露公网；无跨客户筛选、账号鉴权或集群配置。

## detect / store / reconcile

输入输出在 `app/content/models.py`；业务方法返回 Pydantic 对象。CLI/MCP 包装为 `{success, data, error}`。success 表示执行完成，data.passed 表示稿件是否通过，两者必须分别检查。与总方案伪代码的顶层 passed 不同，人员 6 消费时要读取 data.passed。

`detect` 输入：script、内容模块 job_id、content_version_id；两个 ID 是 UUID，版本 ID 由内容持久化层生成。所有比较都在本项目合格稿集合，无 customer_id。

```powershell
.venv/Scripts/python.exe -X utf8 -m app.content.cli detect --input examples/similarity/detect.json
```

响应示意（数字只展示结构）：

```json
{
  "success": true,
  "data": {
    "passed": false,
    "reason": "SIMILARITY_BLOCKED",
    "max_similarity": 0.945,
    "threshold": 0.85,
    "matches": [{
      "content_version_id": "33333333-3333-4333-8333-333333333333",
      "job_id": "44444444-4444-4444-8444-444444444444",
      "score": 0.945,
      "script_excerpt": "命中的历史稿原文片段，用于人员 5 修订。"
    }],
    "profile": {
      "model_id": "BAAI/bge-m3",
      "model_revision": "local-sha256:2b0617a475299ad48c2346dcab71d07f7adb4887694de1edb4c0fba6b858bd41",
      "dimension": 1024,
      "index_version": "bge-m3-dense-cls-l2-cosine-v1",
      "pooling": "CLS",
      "normalization": "L2",
      "distance": "Cosine",
      "preprocessing": "raw-no-instruction-v1"
    }
  },
  "error": null
}
```

有效空库或排除自身后无历史：passed=true、reason=NO_HISTORY_MATCH、max_similarity=null、matches=[]。有低分历史也保留真实最高分，不返回伪造的 0。命中反馈最多包含前 1000 字原文，人员 5 不应将这段文本当作系统指令。

`store` 输入在 detect 字段基础上增加 approval：approval_id、job_id、content_version_id、script_sha256、checks。只接受所有 required_checks 存在且为 true、同作业、同版本、同正文 SHA-256 的审核快照。approval_id 引用人员 4 的真实持久化审核记录；**本模块不拥有该记录数据库，因此快照必须由可信编排层读取，不能接受不可信调用方自我声明审核通过。**

```powershell
.venv/Scripts/python.exe -X utf8 -m app.content.cli store --input examples/similarity/store.json
.venv/Scripts/python.exe -X utf8 -m app.content.cli reconcile --input examples/similarity/detect.json
```

store.json 是合成演示数据，仅用于临时实验库，不作为生产审批。store 返回 saved、point_id、content_version_id、index_version；失败时 data=null 和结构化错误。reconcile 返回相同字段，saved=false 表示有效索引中未找到该版本；集合丢失或断连返回错误，不能理解为未写入。

## 幂等、修订与跨库恢复交接

point_id 直接使用稳定 content_version_id。相同版本/正文/作业重放不增加记录；同版本不同正文或作业报 CONTENT_VERSION_CONFLICT。修改正文创建新版本；只排除当前版本，旧合格修订仍比较，失败草稿不入库。

人员 4、6 应按以下顺序接入，外部 Qdrant 与 SQLite 不假设有跨库事务：

1. 在 SQLite 事务里记录审核快照与 pending 写入意图，绑定 job_id、版本、原文 SHA-256、profile 和原始 store 请求。
2. 调用 store；wait=true 后读回核对一致才返回 saved=true，再由人员 4 更新 confirmed。
3. 超时、进程退出或响应丢失时保留 pending/unknown，不把稿件保存标为成功。
4. 重启后从 pending 读取**原请求与原 profile**，调用 reconcile；saved=true 则补记 confirmed；saved=false 用同版本重试 store；冲突或不兼容停止自动重试并处理原因。
5. 数据库连接失败可有限重试，不换版本 ID；具体调度和重试次数由人员 6 决定。

单版本写入由主管顺序调度。当前未提供跨进程的原子 compare-and-set；本期不承诺多个写入者同时用同版本写不同正文的竞态保护。此限制须由人员 6 的单写入者约定保证，不属于已经完成的并发性能优化。

## MCP / Skill

启动（backend 目录）：

```powershell
.venv/Scripts/python.exe -X utf8 -m app.content.mcp_server
```

这是 stdio MCP 进程，由 MCP 客户端管理其 stdin/stdout；终止连接或 Ctrl+C 停止并关闭索引。不得将普通日志写入 stdout。启动前须配置并显式 init。

工具：

- embed(script)：返回 vector 和 profile。
- vector-search(vector, content_version_id, profile)：校验完整模型来源，排除自身，固定 top 10。
- vector-insert(request)：调用同一 store 业务，必须有审核快照，内部重新计算向量，避免任意正文/向量拼装。
- detect(request)：完整判定和命中反馈，优先供主管使用。
- reconcile(request)：重启/未知写入核对。

加载 `backend/skills/similarity-detection/SKILL.md`。没有照搬总方案不存在保证的 deepagents Skill/SkillContext 伪代码；使用已安装 MCP SDK 的真实 FastMCP API。业务能力可直接通过 `open_service(config)` 获取，Skill、CLI、MCP 均复用相同规则。

## 错误码

| code | 含义 | 处理 |
| --- | --- | --- |
| INVALID_CONFIG | 配置缺失、指纹格式/连接模式/超时非法 | 修复配置 |
| INVALID_INPUT | 空文、缺字段或非法类型 | 修复请求 |
| INPUT_TOO_LONG | 超 token 上限 | 按团队策略缩短并新建版本 |
| EMBEDDING_FAILED | 模型不可读、推理失败或无效向量 | 检查本地模型 |
| EMBEDDING_TIMEOUT | 模型加载/推理硬超时 | 有限重试/核对硬件 |
| INDEX_NOT_READY | 集合不存在 | 核对数据目录，显式初始化或恢复 |
| INDEX_INCOMPATIBLE | 模型/维度/profile/历史 payload 不符 | 新版本索引或修复数据，禁止静默清空 |
| VECTOR_UNAVAILABLE | 向量库操作或连接失败 | 修复连接后重试 |
| VECTOR_WRITE_UNCONFIRMED | 写入/读回结果无法确认 | 先 reconcile，再同键重试 |
| CONTENT_VERSION_CONFLICT | 同版本绑定不同正文/作业 | 核对版本分配，禁止覆盖 |
| APPROVAL_REQUIRED | 审核缺项、不通过或与正文不匹配 | 完成正确审核 |

错误结构为 code、中文 message、retryable、details。传输字段解析错误可能先返回 INVALID_INPUT；不能从错误对象推断稿件已通过。
