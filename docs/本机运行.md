# 本机运行与验证

**其他电脑首次使用请先按 [新机器安装与运行](installation.md) 操作**，包含工具获取、安装命令和故障处理。本文记录原开发机器的验证结果。

启动后可访问：<http://127.0.0.1:8765>。API 文档：<http://127.0.0.1:8765/docs>。

## 已跑通的范围

前端页面 → FastAPI → SQLite → 独立 Worker → FFmpeg 合成 → ffprobe 检查 → 浏览器预览。

页面的“环境自检”生成 2 秒测试图案和测试音，分别生成画面与音频，再封装为 MP4。它仅验证本机运行环境，不生成口播或数字人，不调用付费模型，不提交抖音。

已安装后端基础、开发和可选内容依赖，以及前端依赖。`deepagents`、`langchain-openai` 可正常导入；未配置百炼模型或密钥，没有执行模型请求。

## 启动、停止与状态

从项目根目录运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/start.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/status.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/stop.ps1
```

启动脚本使用隐藏后台进程，并保存 PID 与启动时间。停止脚本只停止这些标识匹配的进程。默认端口为 8765，本机 8000 已被其他程序使用。需要其他端口时使用 `scripts/start.ps1 -Port 8766`。

前端生产构建由 FastAPI 提供，无需额外保持 Vite 进程。改动前端后重新构建并重启：

```powershell
npm.cmd --prefix frontend run build
```

首次安装或重建环境：

```powershell
uv sync --project backend --locked --extra content
npm.cmd --prefix frontend ci
npm.cmd --prefix frontend run build
```

## 本机媒体工具

本机发现并复用了 `D:/AI_APP/EVCapture/ffmpeg.exe` 和同目录 `ffprobe.exe`，版本为 2019-10-22 构建。它们已通过本次 H.264、AAC、MP4 合成自检，但后续模型输出的格式兼容性仍需实际核验。

本机路径写在被 Git 忽略的 `config/runtime.local.json`。其他电脑可复制 `config/runtime.example.json` 为该文件，并填写 FFmpeg／ffprobe 路径，或使用 PATH 中的同名程序。不修改系统 PATH。

## 运行数据

- `data/app.db`：环境自检记录和 Worker 心跳。
- `data/assets/diagnostics/<ID>/`：测试画面、音频与最终 MP4。
- `data/logs/`：API 与 Worker 输出日志。
- `data/processes.json`：受管进程标识。
- `data/local-desktop.png`、`data/local-mobile.png`：本次浏览器验证截图。

运行数据、虚拟环境、前端构建产物和本机配置不入库。环境自检完成后保留结果；Worker 重启时将中断的自检标为失败，可重新发起，不将中断记录冒充成功。

## 验证记录

已通过前端 TypeScript 检查与生产构建、Ruff 检查、3 项后端测试。测试覆盖重复提交与并发领取、重启恢复、Worker 离线及跨源提交拒绝。

真实 HTTP 验证得到带视频和音轨的 2 秒 MP4，支持浏览器 Range 请求；浏览器完成点击自检、视频元信息读取、桌面与手机宽度检查，未出现页面运行错误。停止并重新启动服务后，历史记录仍可读取。

构建提示单个 JavaScript 包超过 500 kB，当前不影响本机启动；后续页面扩展时再拆分。测试有第三方 Starlette／AnyIO 弃用提示，不影响本次通过。
