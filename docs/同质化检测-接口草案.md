# 同质化检测接口草案与实验边界

日期：2026-09-23。状态：待人员 4、5、6 评审；本文不是已发布的 HTTP 契约。

正式实现已经落地，最终字段与命令以 [交付与验收](同质化检测-交付与验收.md) 为准；本文保留为设计过程记录。

## 依据和本期范围

依据用户提供的《2026-09-23-口播稿生成系统-MVP简化Skill方案(1).md》与《03-人员3-同质化检测任务单.md》。总方案规定人员 3 负责 similarity-detection-skill 和 vector-mcp；个人任务单规定本期验收及缩减范围。仓库原四人视频系统的编号不能直接当作这份六人口播稿方案的人员编号。

本期检测 script 与本机本项目已入库合格稿的语义相似度，并保存最终合格稿。无 customer_id 必填字段、客户过滤、时间窗口或并发性能优化。人员 6 编排检查及入库时机，人员 4 持久化写入意图和结果，人员 5 使用命中文本改稿。

现有 HTTP v1 仍用于模块作业；本草案先定义内容模块内部接口，不新增 HTTP 路由、不修改公共 Schema。总方案里的 deepagents Skill/SkillContext 和 MCP 装饰器属于伪代码，正式适配前须核实项目锁定 SDK 的真实 API。MCP 是否本期启用由团队确认；保留 embed、vector-search、vector-insert 薄适配边界，不能把业务阈值藏在传输层。

## 模型和索引提案

| 项目 | 实验固定值 |
| --- | --- |
| 模型 | BAAI/bge-m3 |
| 模型 revision | local-sha256:2b0617a475299ad48c2346dcab71d07f7adb4887694de1edb4c0fba6b858bd41 |
| 向量维度 | 1024 |
| 推理 | CPU、float32，CLS pooling，L2 归一化 |
| 文本输入 | 双方均使用原文，不添加单侧检索指令 |
| 距离 | Qdrant Cosine，分数越大越相似 |
| 判定 | top 10 中最高分 >= 0.85 则拦截 |
| 索引版本 | probe-bge-m3-dense-cls-l2-cosine-v1（仅实验） |
| 实验模型超时 | 子进程加载和推理合计 120 秒；超时退出，不返回通过 |
| 长度限制 | 含特殊 token 最多 8192 token；超过时报错，不静默截断 |

模型卡说明：<https://huggingface.co/BAAI/bge-m3>。实验使用用户提供的完整本地权重；master 不是不可变版本，因此对权重、分词器和配置文件分别计算 SHA-256，再对排序后的摘要清单生成本地版本指纹。实验只使用 dense 稠密向量，不启用 sparse/ColBERT，不调用收费 API。8192 token 不是 8192 汉字。阈值 0.85 不是重复字数比例，须根据后续真实业务语料评估误报和漏报。

正式索引绑定模型 ID、revision、维度、pooling、归一化方式、距离、文本预处理和索引版本。任一变化都不得继续混写旧集合；即使维度相同，模型 revision 不同也要拒绝。新模型应创建独立版本的集合，迁移另行安排。

## detect 输入输出

候选输入类型：`script: str`、`job_id: UUID`、`content_version_id: UUID`。script 必须非空。job_id 是内容模块作业编号；版本 ID 由内容持久化层稳定分配，重试保持不变，修改正文必须换版本。

下例仅展示字段，不是实测结果：

```json
{
  "success": true,
  "data": {
    "passed": false,
    "reason": "SIMILARITY_BLOCKED",
    "max_similarity": 0.91,
    "threshold": 0.85,
    "matches": [{
      "content_version_id": "22222222-2222-4222-8222-222222222222",
      "job_id": "33333333-3333-4333-8333-333333333333",
      "score": 0.91,
      "script_excerpt": "命中的历史稿内容，用于人员 5 修订。"
    }],
    "embedding_model_id": "BAAI/bge-m3",
    "embedding_model_revision": "local-sha256:2b0617a475299ad48c2346dcab71d07f7adb4887694de1edb4c0fba6b858bd41",
    "index_version": "probe-bge-m3-dense-cls-l2-cosine-v1"
  },
  "error": null
}
```

建议采用总方案概述的 `{success, data, error}` 包装，业务层返回明确类型，由 Skill/MCP 外层包装。总方案示例把 passed 放在顶层，与该概述不一致：人员 6 需统一读取 `data.passed`；不能未经对齐修改已实现的消费者。

- success 表示执行成功；检测完成但判定不通过时，仍为 success=true、passed=false。
- 过滤当前 content_version_id 后取 top 10，再排序取最高分。不能先取十条再排除自身，导致少查一条。
- 有结果但未超阈值，也返回实际最高分，不能沿用原伪代码的固定 0.0。
- 有效集合无可比历史：passed=true、reason=NO_HISTORY_MATCH、max_similarity=null、matches=[]。不把“没有历史”伪装成“测得相似度为 0”。
- 索引应在显式初始化阶段创建。运行中集合丢失、数据库断连或模型异常返回错误，不自动重建空集合后放行。
- 仅排除当前版本；同一源稿的旧合格版本仍参与比较。若正常改稿业务需要豁免源稿，须与人员 5、6 明确后修改规则，不能隐含按作业排除所有版本。

## store 输入输出和恢复

候选输入：`script: str`、`job_id: UUID`、`content_version_id: UUID`、`approval_ref: UUID`。approval_ref 是人员 4 持久化的审核记录引用，须绑定同一版本、正文 SHA-256 和必需检查集，并由可信内部服务校验已全部通过；不是任意客户端声明的 approved=true。最终字段与审核存储接口由人员 4、6 评审。

输出：`success`、`data.saved`、`data.point_id`、`data.content_version_id`、`data.index_version`、`error`。调用 wait=true 的 upsert 完成且结果可确认后，才返回 saved=true。

1. Qdrant point ID 从稳定版本 ID 确定生成，重试不能使用新的随机 ID。
2. 同版本、同正文摘要、同索引版本重复调用可安全复用或 upsert；同版本不同正文返回 CONTENT_VERSION_CONFLICT，不覆盖历史。
3. 人员 4 先提交 pending 写入意图（绑定正文摘要、版本、索引），人员 3 执行幂等写入，人员 4 再记录 confirmed。
4. 写入后进程崩溃、响应丢失时，保留 pending/unknown，重启按稳定 point ID 核对 payload 摘要和模型/索引版本；匹配则补记 confirmed，未找到则同键重试，冲突则报错。
5. SQLite 和 Qdrant 无跨库原子事务。未知结果不能伪报成功，不能更换版本 ID 重试造成重复。

以上仅规定接口责任，原型只验证固定 point ID 的重复 upsert 和本地持久化重开；未实现审核凭据校验或跨库恢复。

## 错误码提案

错误沿用公共 Error 结构：`code`、中文 `message`、`retryable`、`details`。发生错误时 success=false、data=null，不同时返回 passed=true。

| 错误码 | 含义 | 自动重试 |
| --- | --- | --- |
| INVALID_INPUT | 空文或字段非法 | 否 |
| INPUT_TOO_LONG | 超过模型 token 上限 | 否 |
| EMBEDDING_TIMEOUT | 加载或推理超时 | 有限次 |
| EMBEDDING_FAILED | 模型加载或推理失败 | 按原因，默认否 |
| VECTOR_UNAVAILABLE | Qdrant 连接/请求异常 | 有限次并核对写入状态 |
| INDEX_NOT_READY | 未初始化或集合缺失 | 否，先修复环境 |
| INDEX_INCOMPATIBLE | 模型、维度或索引元数据不匹配 | 否 |
| CONTENT_VERSION_CONFLICT | 同版本绑定不同正文 | 否 |
| APPROVAL_REQUIRED | 缺失或不匹配的完整审核记录 | 否 |
| VECTOR_WRITE_UNCONFIRMED | 写入结果无法确认 | 同键核对后重试 |

## 首个实验和后续验收

实验入口：`backend/prototypes/similarity_probe.py`。从 backend 运行：

```powershell
uv sync --locked --extra similarity-probe
.venv/Scripts/python.exe -X utf8 prototypes/similarity_probe.py --model-path "<本机 BGE-M3 完整目录>"
```

前提：通过 --model-path 提供完整 BGE-M3 目录，包含 pytorch_model.bin、分词器、modules.json 和配置文件。脚本 local_files_only=true，不隐式联网，运行时重新计算文件指纹。实验用临时 Qdrant 本地磁盘库，退出关闭并清理，不影响业务历史。JSON 原始结果包含完整测试向量，默认写入已忽略的 `data/tmp/similarity-probe-bge-m3.json`。

本地模式无服务端口或独立服务进程，运行脚本即开始，结束即停止。它不能证明 Docker Qdrant 服务的网络、鉴权、超时或断连行为；服务端部署验证单独交付。仓库可选依赖组通过 uv 维护，实验不会启动 HTTP 服务或启用生产同质化检测。

固定语料目前覆盖同文、近似改写和不同主题。总方案提出的 20 对相似文本作为下一阶段扩充项，不把首组实验当作已完成 20 对验证。正式实现仍需替身回归测试、模型/维度错误验证、断连验证、审核后入库、跨库恢复以及人员 4、5、6 联调。
